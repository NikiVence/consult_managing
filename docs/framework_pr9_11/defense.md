# Защита ПР9–11 за пять минут

1. Открыть `webapp/schedule/models.py`: показать три модели, ForeignKey, PROTECT, related_name, TextChoices, ограничения длительности и одной активной записи.
2. Открыть миграцию `0002`: сначала добавляются новые поля, затем RunPython переносит отмены и slug, только после этого удаляется старый флаг и включается уникальность. Показать `showmigrations schedule`.
3. Войти студентом и открыть `/bookings/`. Создать запись; применить фильтр статуса и сортировку. Показать `Paginator` и `querystring` в коде. Параметры фильтрации передаются GET, поскольку чтение не изменяет базу.
4. Открыть форму редактирования. Сохранить ту же консультацию с другой длительностью: обновляется существующий ID. Объяснить `instance`, `exclude(pk=...)` и `commit=False`. Длительность 14 вызывает ошибку поля, занятый слот — общую ошибку.
5. Отменить запись: статус меняется, история сохраняется. GET на адрес отмены возвращает 405. POST без CSRF — 403. После отмены слот снова доступен.
6. В админке показать поиск и фильтр статуса, связанные записи консультации. Административные действия не позволяют завершать будущие встречи или физически удалять историю.
7. Открыть `/statistics/`, показать `aggregate` и `values().annotate()`. Затем `inspect_orm`: сравнить N+1 и `select_related`. В SQL-панели видны JOIN и количество запросов.

## Короткие ответы

- **ORM** переводит операции Python над моделями в SQL; QuerySet ленивый, запрос обычно выполняется при итерации.
- **get / filter**: get возвращает один объект или исключение; filter возвращает QuerySet, который может быть пустым.
- **select_related / prefetch_related**: первый использует JOIN для одиночных связей, второй отдельные запросы и объединение в Python для коллекций.
- **aggregate / annotate**: сводный результат по выборке / вычисленное значение у объекта или группы.
- **exists / count**: проверка наличия / количество; для проверки доступности достаточно exists.
- **Form / ModelForm**: произвольные поля / поля и сохранение связанной модели.
- **clean_field / clean**: проверка одного поля / совместная проверка полей.
- **валидация / транзакция**: удобное сообщение пользователю / повторная проверка и согласованное сохранение при конкуренции.
- **SQLite / PostgreSQL**: SQLite в проекте использует IMMEDIATE-транзакции; PostgreSQL поддерживает блокировки строк select_for_update. Многопользовательскую нагрузку PostgreSQL отдельно в этой работе не проверяли.
- **миграция / migrate**: файл описывает изменение состояния схемы и данных; команда применяет его к базе.
- **отмена / удаление**: отмена сохраняет историю; удаление физически убирает строку.

Не выдавать автоматические проверки за прохождение курса. Подтверждение Яндекс Практикума и Git-коммит показываются отдельно.
