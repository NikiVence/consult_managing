# Ответы на контрольные вопросы ПР1

## Основы Python

1. **Основные типы данных.** `int` — целые числа, `float` — вещественные,
   `str` — строки, `bool` — логические значения. Также существуют `None`,
   списки, кортежи, словари и множества; коллекции изучаются на ПР2.
2. **Различия int, float, str, bool.** `45` — число минут (`int`), `0.75` —
   число часов (`float`), `"Анна"` — имя (`str`), `True` — свободный слот (`bool`).
3. **Преобразование типов.** Нужно для обработки данных в нужном формате:
   `input()` возвращает строку, а `int("45")` даёт число для вычислений.
4. **Операции со строками.** Склеивание `+`, повторение `*`, сравнение,
   получение длины `len()`, индексация, срезы, поиск, методы `strip()`,
   `lower()`, `replace()`, форматирование f-строками. Строки неизменяемы.
5. **Операторы сравнения.** `==`, `!=`, `<`, `>`, `<=`, `>=`.
6. **Конструкция if.** Выполняет блок кода, если условие истинно.
7. **if, elif, else.** `if` проверяет первое условие, `elif` — следующее,
   если предыдущие ложны, `else` выполняется, если ни одно не выполнено.
8. **Составные условия.** Объединяются логическими операторами:
   `duration_minutes < 15 or duration_minutes > 90`.
9. **and, or, not.** `and` требует истинности обоих условий, `or` — хотя бы
   одного, `not` отрицает условие. `and` и `or` вычисляются с сокращением:
   второй операнд проверяется только при необходимости.
10. **Модуль Python.** Единица организации кода с функциями, переменными
    и другими объектами; часто это отдельный файл `.py`.
11. **import.** Подключает модуль или его объекты для использования в программе.
12. **Импорт модуля и объекта.** После `import datetime` обращение имеет вид
    `datetime.timedelta(...)`, после `from datetime import timedelta` —
    `timedelta(...)`.

## Рабочее окружение

13. **Виртуальное окружение.** Изолирует интерпретатор и установленные
    зависимости проекта от других проектов. Создаётся `python -m venv .venv`.
14. **IDE.** Интегрированная среда разработки: редактор, запуск, подсказки,
    отладчик и средства работы с проектом. VS Code с расширениями Python
    предоставляет нужные возможности.
15. **Git.** Система контроля версий: хранит историю изменений, позволяет
    сравнивать версии и организовать совместную разработку.
16. **Репозиторий.** Проект и его история версий; локальные служебные данные
    Git находятся в `.git`. Удалённый репозиторий хранится на сервере.
17. **Commit.** Зафиксированное состояние подготовленных изменений
    с автором, сообщением и идентификатором. Перед ним выполняют `git add`.
18. **.gitignore.** Задаёт шаблоны неотслеживаемых файлов, которые Git должен
    игнорировать: например, `.venv/` и кэш. Уже отслеживаемые файлы он не удаляет.
19. **README.md.** Объясняет назначение, устройство и запуск проекта,
    перечисляет функции и план развития.
20. **Отладка.** Исследование работы программы для поиска и исправления ошибок.
21. **Breakpoint.** Точка остановки, в которой отладчик приостанавливает
    выполнение и позволяет изучить состояние программы.
22. **Пошаговое выполнение.** Позволяет проследить изменение переменных
    и выбранные ветви. Step Over выполняет строку без входа в функцию,
    Step Into входит в функцию, Step Out завершает текущую функцию.

## Индивидуальный проект

23. **Задача приложения.** Упрощение записи студентов на консультации
    и управления расписанием преподавателей.
24. **Пользователи.** Студенты, преподаватели, сотрудники учебного отдела.
25. **Сущности.** Пользователь, дисциплина, консультация, запись;
    запись связывает студента с консультацией преподавателя.
26. **Планируемые функции.** Расписание, создание и изменение консультаций,
    запись и отмена, вход пользователей, разграничение прав, REST API.
27. **Текущий сценарий.** Ввод имени и длительности, проверка свободного
    будущего слота и допустимого времени, расчёт окончания, подтверждение
    записи и изменение флага доступности.
28. **Конструкции Python.** Простые типы, переменные, арифметика, сравнения,
    преобразование `int`, `if`/`elif`, `or`/`not`, функции, импорт, f-строки.
29. **После ООП и Django.** Классы сущностей, база данных и ORM,
    веб-страницы, формы, аутентификация, роли пользователей и API.
30. **Почему подходит для веб-приложения.** Несколько пользователей работают
    с общим расписанием; нужны постоянное хранение, связанные сущности,
    права доступа и доступ через браузер.

## Дополнительно для демонстрации

- `pytest` запускает тесты, а `assert` проверяет ожидаемый результат.
- `ruff check .` проверяет оформление и типичные ошибки кода.
- Ошибка `hours=duration_minutes` нарушает единицы измерения:
  `45` начинает означать часы. Исправление — `minutes=duration_minutes`.
- `.venv` не отправляется в Git: её воссоздают локально, зависимости проверок
  устанавливают из `requirements-dev.txt`.
- Учебная запись не сохраняется между запусками. Постоянное хранение
  появится при изучении файлов и базы данных.
