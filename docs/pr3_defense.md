# ПР3: как объяснить проект на защите

## Короткое объяснение

«Я развил систему управления консультациями: выделил классы пользователей,
консультаций и записей. Запись хранит ссылки на конкретного студента
и консультацию. Операции над состоянием перенесены в методы. Меню работает
с коллекциями объектов, а JSON сохраняет их данные и связи между запусками».

## Где показать ООП

1. Откройте `models/users.py`: User — общая основа, Student и Teacher —
   наследники. Наследование оправдано отношением «студент является пользователем».
2. Покажите `__init__`: он инициализирует уже созданный экземпляр;
   `self` — ссылка на этот конкретный объект. Создание экземпляра в Python
   начинается с `__new__`, затем обычно вызывается `__init__`.
3. `id` и `name` — атрибуты экземпляра. `role`, `MIN_DURATION`,
   `MAX_DURATION` — атрибуты классов.
4. `__str__` возвращает строку для `str(obj)` и `print(obj)`.
   В подклассах метод переопределён: одинаковый вызов работает с разными ролями.
5. В `models/bookings.py` покажите `self.student` и `self.consultation`:
   это объекты, а не только ID. Можно обратиться к
   `booking.consultation.teacher.name`.
6. Покажите `cancel()`: меняет `_is_cancelled`. Публичное свойство
   `is_cancelled` только для чтения. Подчёркивание обозначает внутреннее поле.
7. `ends_at` вычисляется по началу и длительности, а не хранится отдельно;
   `@property` позволяет обращаться без круглых скобок.
8. `validate_duration` — `@staticmethod`: не получает `self` и не использует
   состояние конкретного объекта. `@classmethod`, в отличие от него,
   получает класс `cls` и может служить альтернативным конструктором.

## Функции и методы

Метод привязан к объекту: `booking.cancel()` изменяет конкретную запись.
Поиск, сортировка и сохранение работают с наборами объектов, поэтому
остались обычными функциями. `main.py` отвечает за диалог с пользователем.

## JSON

Объект нельзя напрямую сохранить обычным `json.dump`. В `save_data`
из объектов создаются словари из простых данных. Связи записываются как ID.
`load_data` сначала создаёт пользователей, потом консультации, потом записи.
По ID выбираются уже созданные объекты; поэтому ссылка на одного студента
может быть общей у нескольких записей.

Несуществующая ссылка, повторный ID, неправильная роль или повреждённый
JSON считаются ошибкой. Существующая база при этом не заменяется пустой.

## Наследование и композиция

Student **является** User — наследование. Booking **содержит ссылки на**
Student и Consultation — композиция (связанные сущности имеют собственную
жизнь). Запись не является студентом, поэтому наследовать её от Student
было бы неверно.

## Декораторы

Декоратор принимает функцию или класс и добавляет/меняет поведение.
Функция-обёртка вызывает исходную функцию, выполняя действия до или после.
`*args` и `**kwargs` позволяют передавать её позиционные и именованные
аргументы, а `functools.wraps` сохраняет имя и документацию исходной функции.
В проекте применены готовые `property` и `staticmethod`; собственный
декоратор и `classmethod` для текущего сценария не требуются.

## Демонстрация

```powershell
.\.venv\Scripts\python.exe demo.py
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 .
```

В `demo.py` видно: создание объектов → успешная запись → отказ при повторе →
отмена → новая запись → сохранение JSON → восстановление общих ссылок.
В меню можно повторить сценарий самостоятельно и затем перезапустить программу.

## Что изменилось в тестах

Проверки времени окончания теперь обращаются к `booking.ends_at`.
Проверки подтверждения вызывают `booking.confirmation()`.
Вместо флага доступности проверяется коллекция записей.
Добавлены проверки наследования, ролей, отмены, связей объектов,
сохранения и загрузки JSON, пересечений и ошибок файловой системы.

## Честные ограничения

В исходной папке была версия ПР1; отдельная ПР2 отсутствовала.
Меню, коллекции и JSON добавлены при текущей доработке.
Программа рассчитана на локальное использование одним процессом,
без регистрации и серверной базы. Следующий этап — Django.
Прохождение курса показывается в личном аккаунте. Код, тесты и отчёт
представлены в репозитории проекта.
